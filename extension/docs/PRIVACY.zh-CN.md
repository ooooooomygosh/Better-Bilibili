# 隐私与权限

## 默认状态

必需 API 权限仅 `storage`。页面脚本匹配 B 站站点；因此浏览器仍会提示可读取和更改对应站点内容，不能说它“没有站点权限”。没有 `proxy` 权限（2.3.0 起移除了「海外访问」代理分区，见下）。

本分支没有统计上报服务，没有第三方解析服务器，没有账号密码输入框。仅按上游方式读取当前网页已拿到的播放数据并向允许的媒体 CDN 发请求；并不代表 B 站网站自身停止其正常分析或账号请求。

## 保存什么

加载策略、主题等偏好在 chrome.storage.sync：开启浏览器账号同步时可能通过浏览器厂商同步。首页推荐快照在 chrome.storage.local：不进入 sync、不发送给本分支服务器，最多 25 批／会话、36 卡片／批、7 天；多会话定期清理，目标最多 20 组。长时间打开的多个页面和存储配额可能影响实际可保留数量；清空入口在设置页。

快照保存标题、UP 主、封面链接、时长、统计文本和规范化视频链接。视频 URL 去掉查询参数和片段；不是保存原始页面、Cookie、播放签名或下载文件。点击历史卡片、加载封面仍会访问 B 站／其图片服务。会话标识写入当前站点 sessionStorage 以跨刷新保持，复制标签页可能继承标识；关闭标签页后不保证找回原会话。

没有承诺这个文件夹中的测试日志可以安全地替代你真实的诊断日志：向任何人分享真实网页日志前仍需删除带签名的播放地址和账号信息。

## 代理（已移除）

2.3.0 起不再包含「海外访问：接入已有可信代理」。原因：Chrome 不允许把 `proxy` 列为可选权限（扩展页报 “Permission 'proxy' cannot be listed as optional”），所以这个功能实际上从来无法授权；改成必需权限会让所有人安装时多一条“读取和更改代理设置”的警告，并在更新时停用扩展直到重新同意，对一个小众功能不值得。扩展更新后会删除旧版本可能留下的代理地址（`flowProxy`）。需要代理请继续使用系统代理或你已有的代理软件 / 扩展。

## 代码信任边界

媒体拦截必须运行在 MAIN world，延续上游设计；它与网页同处执行环境，不是对恶意网页的安全隔离沙箱。配置桥保留上游通信方式。新增页面 telemetry 是显示用数据，不会触发任何权限或浏览器设置变更。历史用 textContent 和经主机／协议校验的链接呈现，不反序列化原始 HTML。

这是源码审阅和本地测试的结果，不是独立安全审计认证。

## 1.1.0 诊断与错误标记

Debug 面板的“复制诊断信息”仅在用户点击时生成文本并尝试写入剪贴板；没有自动上传端点。媒体下载 URL 整段隐藏，其他 URL 查询／片段与常见敏感字段做脱敏；公开页面路径、浏览器版本、设置和调试事件仍可能体现使用情况，分享前应检查。剪贴板不可用时显示只读文本供手动复制。

根据上游修复，升级时会一次性移除五个明确的旧编码错误缓存键，而不是清空 B 站全部本地数据或 Cookie：enableHEVCError、enableAV1Error、decodeHEVCError、decodeAV1Error、bilibili_decode_error_obj。接管运行期间仅拦截这几类失败标记，防止插件接管错误被站点长期误记为浏览器不支持编码。

## 2.1.0 无限下滑与节流阀

- **无限下滑**（默认关闭）：开启后，扩展会在首页向 `api.bilibili.com` 的首页推荐接口与 `nav` 接口发请求，与 B 站网页自己加载推荐时用的是同一组接口；请求附带你在 B 站的登录 Cookie，由浏览器按 B 站自身的 CORS 规则发送，扩展不读取、不保存 Cookie。签名用的两段公开 key 会缓存在本机 `chrome.storage.local`（`flowWbiKeys`，12 小时有效）。推荐结果只显示在页面上，不写入存储。
  - **悬停预览**（2.3.0）：鼠标停在无限下滑卡片的封面上时，向 `api.bilibili.com/x/player/videoshot` 请求该视频的预览图，与 B 站原生卡片的预览来源相同；不写入存储。
  - **稍后再看**（2.3.0）：只在你点击按钮时，向 `api.bilibili.com/x/v2/history/toview/add` 发送一次请求，把这条视频加入你自己的「稍后再看」。B 站要求这类写操作附带防跨站令牌，所以这一次点击会从当前页面读取 `bili_jct` 这一个 Cookie 的值作为 `csrf` 参数（与 B 站网页自己的做法相同）；不读取其他 Cookie，不保存、不上传到别处。
  - **不感兴趣**（2.3.0）：只在本机生效。被隐藏的视频 BV 号保存在 `chrome.storage.local`（`flowDislikes`，最多 500 条），「不想看此 UP 主」保存 UP 主的数字 ID（`flowHiddenUps`，最多 500 个），都不会发给 B 站。
- **节流阀**：观看用量（秒数、视频 BV 号、重置时间）只保存在本机 `chrome.storage.local`（`focusUsage`），不上传。

## 自律锁（2.3.0）

- 开启后，锁的状态保存在本机 `chrome.storage.local`（`focusLock`）：冷却期、已批准的额度、等待生效的改动、输错次数。
- 设置了密码时，只保存随机盐和 PBKDF2-SHA-256（210000 次迭代）的哈希结果，不保存密码本身，也不上传。
- 首页开关的副本会写入 B 站页面的 `localStorage`（`btr-flow-flags`，只含几个布尔值），用于页面一开始就隐藏轮播，减少闪烁。
- 扩展页面配色（2.3.0）：页面脚本把最近一次检测到的 B 站深浅色写入 `chrome.storage.local`（`biliTheme`，只有「是否深色」和时间），弹窗 / 设置页 / 欢迎页据此配色；选项「扩展页面配色」保存在 `chrome.storage.sync`（`uiTheme`）。扩展页面还会在自己的 `localStorage` 缓存上次的配色（`btr-ui-theme`），避免打开时闪白。都不会发送到任何地方。

## 观看周报（2.6.0 起，2.7.0 更新）

- 设置「观看统计」（`statsEnabled`，默认开启）打开时，扩展在本机 `chrome.storage.local` 的 `watchStats` 里按天记录：主播放器真实播放的秒数、播放满 10 秒的视频个数、按小时（0–23 点）的分布、UP 主的数字 ID 与名字及对应秒数（每天最多 30 个，从视频页面上已显示的 UP 主链接读取，不额外请求）、额度用完 / 番茄钟休息的次数，以及「本周是否已提醒过」。
- 当天的视频 BV 号列表只用于「同一视频一天只算一次」，午夜后保留最多 30 秒以接收跨日的最后一次播放记录，之后在下一次归档时删除，只留个数。最多保留最近 10 周，更早的自动删除。
- 只写在本机，不进入 sync，不发送给任何服务器；观看额度关着时也只记录、不拦截。设置页「观看统计 → 清空统计」可一键删除，关闭开关后不再记录。
- 周报页面、分享图、分享文字和 CSV 都在本机生成。分享图和文字默认隐藏 UP 主名字，可以主动取消；只有你点击下载、复制或系统分享时才导出。系统分享由浏览器和操作系统处理所选目标，扩展不会自动发送。CSV 仅包含日期、秒数、视频数和踩刹车次数，不包含 BV 号、UP 名字或 ID。
- 周报页面在自己的 `localStorage` 记住「隐藏 UP 主名字」这个勾选（`btr-report-hide-v2`）。

## 空降助手（BilibiliSponsorBlock）

- 打开视频页时，向 `https://bsbsb.top/api/skipSegments/<前缀>`（不通时改用 `www.bsbsb.top`） 查询片段；`<前缀>` 只是 BV 号 SHA-256 的前 4 位十六进制，同一前缀覆盖大量视频，可以减少直接暴露具体 BV 号，但不能保证匿名；服务仍可看到请求的网络来源和时间。请求不带 Cookie。
- 为了区分分 P，会请求 B 站公开的 `api.bilibili.com/x/player/pagelist`（不带 Cookie）。
- 只有你主动按 ; 提交片段时，才会在本机生成匿名 ID（存 `chrome.storage.local`，不同步），并与 BV 号、cid、时间点、分类一起发送给 bsbsb.top。
- 在弹窗关闭空降助手后不再发出任何上述请求。


## 场景模式、评论属地与链接分享（2.7.0）

- `sceneMode`、学习模式是否保留评论、评论属地显示开关属于 `chrome.storage.sync` 偏好。场景模式不改写额度、自律锁或个人首页设置。
- 首页主题入口在点击后打开 B 站搜索，将输入的关键词作为普通搜索参数发送给 B 站；扩展不另存搜索词。
- 评论属地仅从当前页面的 `reply_control.location` 或原生标签读取并显示。兼容 Shadow DOM 的脚本运行在 MAIN world；没有额外网络查询，不记录评论、作者或地区，不推测精确 IP。
- 「复制干净视频链接」仅在点击时写入剪贴板，保留公开视频身份与合法分 P，移除追踪参数，不附加登录数据或媒体签名。

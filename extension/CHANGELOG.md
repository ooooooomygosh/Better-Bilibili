## 2.4.0 — 2026-10-10

### 新增：屏蔽规则（关键词 / UP 主 / 标签）
- 快捷面板「首页」→「屏蔽」，或设置 →「屏蔽」。三份列表：**标题关键词**（不分大小写和全角半角，写成 `/正则/` 可用正则）、**UP 主**（名字完全一致或 UID）、**视频标签**（B 站视频页下方的标签，完全一致）。
- 首页原生推荐和无限下滑都会过滤：每次换一批、每加载一批都重新过滤，被屏蔽的卡片连同它占的格子一起隐藏，后面的卡片顺位补上。
- 操作栏显示「已屏蔽 N 个」，悬停能看到每张卡片是被哪条规则屏蔽的；无限下滑的分隔条写着这一批屏蔽了几个。
- 无限下滑卡片的 ⋮ 菜单：「屏蔽 UP 主」按 UID 记录（改名也有效）；新增「按标签屏蔽…」，列出这个视频的标签，点一下就屏蔽。都可以撤销。
- 规则存在浏览器同步存储里，换电脑也在；设置页可以导出、导入（合并）、清空。原来「不想看此 UP 主」的本地记录升级时自动并入 UP 主列表。
- 推荐接口不带标签：设置了标签规则后才逐个查询 B 站的公开标签接口，最多同时 3 个，结果缓存在本机（最多 3000 条）。没设标签规则就不会多发任何请求。
- 屏蔽规则改了之后，屏幕上已经显示的匹配卡片会淡出，后面的卡片平滑补位。

### 首页：「换一批」和「无限下滑」分成两种模式
- 第一次打开首页时，推荐区上方会让你选一种（欢迎页里也能选）；之后在快捷面板「首页」顶部的两张模式卡里随时切换。已经开着无限下滑的老用户直接算作选了「无限下滑」。
- **换一批模式**：保留「上一批 / 第几批 / 下一批 / 换一批」和本地回看；新增**跨批去重**——这次打开页面后前几批出现过的视频，换一批之后不再显示（可关）。只和本次打开页面后的批次比较，重新打开首页不会把首屏藏掉一半。
- **无限下滑模式**：没有「换一批 / 上一批 / 下一批」，也不再记录换一批历史；操作栏只写「♾ 无限下滑 · 第 1 批 · 往下滑自动加载」，原生「换一换」按钮也隐藏。
- 快捷面板和设置页只显示当前模式自己的选项。

### 新增：卡片开关
- 首页可以单独隐藏**直播卡片**（直播间卡片和直播楼层）、**番剧 / 影视 / 课堂等楼层卡片**、**轮播图里的广告**。

### 新增：全站净化（快捷面板「净化」标签页 / 设置 →「净化」）
- 参照 AdGuard 中文过滤和烦人元素过滤里正在维护的 B 站规则，按页面单独开关：视频页右侧广告与推广卡片（广告、商品、游戏、活动）、小窗直播推荐、搜索结果里的广告、动态里的广告与带货、「检测到广告拦截」提示、未登录时的登录提示、「打开 App」按钮、顶栏「下载客户端」入口。
- 只按明确的广告标记和广告位隐藏，不按标题或 UP 主判断。广告类默认开，其余默认关。
- 规则是普通 CSS，页面一开始加载就生效；上次的开关状态镜像在站点本地存储里，广告不会先闪一下再消失。B 站站内切换页面时会重新判断哪些规则适用。

### 和 AdGuard 等去广告扩展一起用
- 用 AdGuard 浏览器扩展实际使用的过滤引擎（ExtendedCss、Scriptlets）和它默认开启的过滤规则（基础、中文、跟踪保护、烦人元素、社交，共 1.8 万多条通用隐藏规则和全部 B 站规则），在 Chromium 里和本扩展一起加载测试：首页卡片、无限下滑、换一批、快捷面板等本扩展的 7000 多个界面元素都没有被误伤，没有报错，也没有互相反复修改页面。两边隐藏的是同一类东西，叠在一起只是重复隐藏。
- 本扩展用到的 CDN 节点都在 `bilivideo.com` 下，不受 AdGuard 屏蔽 PCDN 节点和隐藏 Referer 的影响；`fetch` / XHR 的包装都是透传的，和 AdGuard 的脚本可以叠加。
- 净化标签页、设置页和常见问题里写明了：遇到排版问题时，先关掉本扩展对应开关或在去广告扩展里暂停 B 站规则，确认是哪一边引起的。

### 修复
- 首页「已加载卡片强制显示」的规则加上屏蔽 / 去重排除后，不再抬高优先级（合并成一个 `:not()`），广告卡片仍然在第一次绘制时就被 `:has()` 规则隐藏，不会先闪一下。
- 换一批时判断「这一批是否刷新完整」改为按 B 站实际渲染的卡片数，被去重或屏蔽掉的卡片不再让刷新一直等到超时。
- 快捷面板里的输入框打字时，按键不会传到 B 站页面（视频页按 F 不会进全屏）。

## 2.3.0 — 2026-10-09

### 新增：自律锁（防止随手放宽额度）
- 设置 →「自律锁」。开启后，**收紧**额度（缩短时长、开启额度、开严格模式）立即生效；**放宽**（加时长、关额度、关严格模式、缩短冷却期、解除锁）要排队等冷却期（1 小时 / 6 小时 / 24 小时 / 3 天 / 7 天），或输入密码立即生效。
- 密码可选，只保存加盐的 PBKDF2-SHA-256 哈希（21 万次迭代），不保存密码本身；连续输错 5 次会暂时锁定输入（5 分钟起，逐次加倍）。忘了密码就只能等冷却期——没有后门。
- 锁开启时，「再看 5 分钟 / 再看 1 个 / 跳过休息」需要密码；没设密码就不提供。
- 守卫在后台 Service Worker：快捷面板、弹窗、设置页都只能通过它改额度；直接写入存储的放宽改动会被改回并排队。等待中的改动可以在面板或设置页一键撤销。
- 老实说：这是给自己设的门槛，不是防破解。卸载扩展、用开发者工具改存储都能绕过。
- 不需要新增浏览器权限。

### 无限下滑：卡片和原生一模一样
- 加载出来的卡片改用 B 站原生卡片的结构和类名，直接吃 B 站自己的样式：字体、圆角、深色模式、悬停效果都与原生一致，B 站改版时也会跟着变。
- 悬停封面会预览视频画面（逐帧滑动，与原生的预览图来源相同）。
- 稍后再看：悬停右上角一键加入（使用页面自己的登录状态）。
- 「撤销」从结构上不可能再打开视频（登录后曾出现点「撤销」却打开了新标签）：选了「不感兴趣」后，整张卡片被换成一个普通的占位块（说明 + 「撤销」），它不在任何链接里、也不带 B 站卡片的类名；被换下的卡片里所有链接暂时去掉 `href` / `target`。B 站页面先注册的委托监听（mousedown / pointerup / click / auxclick / 中键）都找不到可打开的东西；「撤销」把原来那张卡片和链接原样放回——放回同一个格子，并清掉可能残留的淡入淡出动画和内联样式，保证它真的重新可见（实机反馈过撤销后卡片没回来）。
- ⋮ 菜单挂在卡片外面（固定定位），菜单项的点击不会被当成点卡片；靠近窗口底部时向上展开。
- 卡片右下角 ⋮ 打开和原生一样的小菜单：添加至稍后再看、不感兴趣、不想看此 UP 主。后两项只在本插件生效（B 站网页没有公开的反馈接口，不会影响你的推荐算法）。选了之后原位显示和 B 站一样的提示：模糊封面上写「已减少此类推荐」，带「撤销」、右上角 × 和下方「知道了」。提示**在屏幕上时永远不会自己收起**：只在点 × / 知道了，或你自己滚动页面把它滚出屏幕时才收起——而且它累计在屏幕上至少 8 秒、并且完全离开视口超过 1 秒才算（页面重排把它挤出屏幕、或只离开一下都不算；之前「鼠标离开 2.5 秒后收起」和「一离开视口就收起」会让它 2–3 秒就消失）；收起后后面的卡片平滑挪位（FLIP 动画），有备用卡片时补在这一批末尾，保证这一行是满的。
- 每批数量按首页当前的列数取整，最后一行不再缺几张：5 列时 24 → 25、36 → 35、12 → 10，多出来的留给下一批。
- 底部始终有两行骨架卡片表示还在加载，不会出现大块空白；卡片落地后立即可见，只有刚好在屏幕里的卡片播放错开的淡入，不再等待观察器把卡片从透明变出来；封面加载前显示占位底色。
- 右侧「第 N 批」在屏幕中间正好是分隔条或骨架时不再跳回第 1 批。
- 遇到风控不再只显示错误码：说明发生了什么、会不会继续请求，提供「重试」和「切到『稳』再试」，原始错误放在可展开的详情里。

### 跟随 B 站深浅色（实时）
- 按 B 站现在的做法检测主题：首页切换 `<html>` 上的 `bili_dark` 类，视频页替换 `bili-theme/light.css` ↔ `dark.css` 样式表地址。同时检查主题变量 `--bg1` / `--Ga0`、页面底色和系统设置；监听 html / body 属性、`<head>` 里样式表的增删和地址变化、样式表加载完成、标签页切回，并以每 4 秒一次的轻量检查兜底。
- 快捷面板、额度提醒浮层、⋮ 菜单和无限下滑卡片都在打开状态下即时切换，不用刷新。
- 弹窗、设置页、欢迎页也能跟随 B 站：设置 →「快捷面板与外观」→「扩展页面配色」：跟随 B 站（默认）/ 跟随系统 / 浅色 / 深色。页面脚本把最近一次检测到的 B 站深浅色记在本地（`biliTheme`），扩展页面打开时读取、变化时实时切换；还没去过 B 站时按系统设置。上次的配色会缓存，深色下打开不会先白一下。深色版的渐变头图、阴影、遮罩、保存条都单独调过。

### 播放：慢网络保护（排查「开插件黑屏、卡死」）
- 排查结论：本分支的播放内核（page-hook / native-mse-player / native-range-transport / idm-downloader / cdn-resolver / range-core）与 main 只差版本号，黑屏不是这次 UI 改动引入的。根因是网络：测试环境到 upos 节点的未缓存分段经常只有 24–100 KB/s（首字节 4–11 秒），关掉插件也只有几十 KB/s。在这种网速下，接管播放器的老逻辑会选更高清晰度、多节点竞速分摊带宽，失败后 4 秒自动重新接管，于是长时间黑屏。限速 400 kbps 复现：main 和本分支表现相同；未能复现页面卡死（主线程心跳延迟始终 < 0.3 秒）。
- 新增：接管后 20 秒内（且你确实在等播放）一个媒体分段都没拿到，就把视频交还给 B 站自己的播放器，并且这个视频不再自动重新接管（页面上的提示里有「重新接管」按钮，可以手动再试）。首个分段之前就出现网络类致命错误，也不再自动重试。
- `SourceBuffer.buffered` 的兼容补丁改为真正接管之后才安装：B 站自己的播放器读取已移除的 SourceBuffer 抛出的 InvalidStateError 不再被算到扩展头上（扩展错误页里那两条）。「Extension context invalidated」来自重新加载扩展后旧页面里的脚本，刷新页面即可；DVRWindow TypeError 和 blob ERR_FILE_NOT_FOUND 是 B 站播放器自身的报错。

### 移除：海外访问代理
- 删除设置页「海外访问：接入已有可信代理」及 `optional_permissions: ["proxy"]`。Chrome 不允许 `proxy` 作为可选权限（扩展页警告 “Permission 'proxy' cannot be listed as optional”），这个功能从来无法授权；改为必需权限会给所有用户加安装警告、并在更新时停用扩展等待重新同意，因此选择移除。更新后删除旧的 `flowProxy` 存储项。

### 快捷面板
- 切换标签时面板高度平滑过渡（220ms，尊重「减少动态效果」）。
- 面板层级放在 B 站顶栏之下：头像、消息等下拉菜单会盖在面板上面；面板也不会伸到顶栏底下。网页全屏 / 全屏播放时仍在最上层。
- 自律锁密码输错：错误直接显示在密码框下面，输入框轻微摇动，面板不再整块重建。
- `Alt+T` 是真正的开关：焦点在面板里（快捷面板的 shadow root 内）、在播放器上、正在打开时再按一次，都会关上；在 window / document / shadow root 三处监听，不怕页面自己的按键处理。
- 打开前先算好位置再显示，从停靠的角落轻轻放大出现（不再上滑），打开后不随滚动或内容变化移动位置。
- 打开后以**顶边**固定：打开前先量出最高的标签页并预留空间，切换标签（例如更矮的「油门」）时顶边不动，只有底边随高度平滑变化（之前底边固定，切到油门时整个面板顶部从 185px 跳到 330px）。
- 面板顶部始终在 B 站顶栏下方（检测 `.bili-header` / `#biliMainHeader` 的底边，至少距顶 64px），最大高度随之限制，内容在面板内部滚动；顶栏滚动时滑出来盖到面板时，面板顶边下移让开、底边不动。
- 「完整设置」第一次点击就能打开：后台被唤醒时可能丢掉第一条消息，现在面板会等后台回复，没回复就自动再发一次；后台用新标签页打开（已有设置页就切过去），失败再退回 `openOptionsPage`。「使用指南」同理。
- B 站顶栏的下拉菜单（头像、消息、历史……，半透明带毛玻璃）盖在面板上时，面板平滑淡出，菜单收起后再淡入，不再透出一团乱。
- 设置变化时原地更新，不再整块重建：开关的滑动动画不会被打断，用量条只在第一次打开时从 0 长出来，之后平滑过渡。
- 跟随 B 站深浅色主题实时切换；分段选择器加了滑块动画。
- 键盘：`←` `→` `Home` `End` 切换标签（roving tabindex、`aria-controls`、`tabpanel`）；`Tab` 在面板内循环；在输入框 / 评论框里按 `Alt+T` 不再误开面板。
- 悬浮按钮会自动避开 B 站右下角的工具栏；修复面板右侧偏移在窗口变化后被重置的问题。
- 自律锁开启时，面板里显示等待生效的放宽改动，可撤销或输入密码立即生效。

### 额度提醒浮层
- 自律锁密码输错时，错误显示在密码框下方并轻微摇动。
- 跟随 B 站深色模式；默认焦点不再落在「离开 B 站」上，避免回车误关页面。
- 自律锁开启时，「再看一会儿」需要密码，并说明原因。

### 首页
- 「隐藏广告卡片」跟上 B 站现在的广告卡片结构：登录后首页混在推荐里的广告（如「腾讯 WorkBuddy」，封面右下角写「广告」）以前漏网，因为旧规则只认已经不存在的 `bili-video-card__info--ad` 类名。现在按 B 站首页脚本里的卡片模板识别：封面统计区里直接出现「广告」文字（代替时长）、创意广告的火箭图标、指向 `cm.bilibili.com` 的广告跳转链接，以及旧类名。规则用 CSS `:has()` 在页面开始加载时就生效（不会先闪一下再消失），隐藏的是整个网格格子，后面的卡片顺位补上、不留空洞；遇到不认识的新结构，只要封面上有一个恰好写着「广告 / 推广」的小标签，也会由观察器补上标记。不按标题或 UP 主名字里的关键词屏蔽。
- 隐藏广告后首页原生推荐区最后一行不再留空：B 站首屏卡片数是固定的（第 12 张起由 B 站自己隐藏），藏掉一张广告就会在最后一行留下空格。开启「无限下滑」时，扩展用一张备用推荐卡（不会在下面的批次里重复出现）补满这一行；按实际排版逐行计算，轮播、直播楼层卡和 B 站自己的错位样式都不影响。原生区恢复完整时备用卡自动撤回，不会单独占一行。备用卡和下面的卡片一样有 ⋮ 菜单。之前「已加载」的原生卡片强制显示规则会把 JS 标记的广告重新显示出来，也一并修正。
- 无限下滑请求的推荐里，`is_ad`、`goto` 不是视频、`business_info`、`ad_info`、直播间、`cm.bilibili.com` 链接的条目都会跳过。
